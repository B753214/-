# Atlas 知识问答 Agent

基于 Python、FastAPI 和 LlamaIndex 的中英文 RAG 问答应用。用户可输入文字或音频，应用只输出文字。知识来源为 Notion 页面和服务端 PDF；问答页不提供文档上传功能。

问答先判断是否需要查资料，再选择资料来源。稳定的数学、算法、协议和成熟技术概念由模型直接回答；内部资料走 Notion/PDF 知识库；当前信息、高风险事实和陌生的新名词需要外部核实。问题中给出 Notion 链接时，只检索已导入的本地页面分块；普通网页链接可走网络提取。中文问题用中文回答，英文问题用英文回答。

知识库检索使用向量与可选 BM25 召回、RRF 融合、可选重排。网络搜索通过 Tavily 完成；对比和调研问题可拆成 2–3 个并行查询。常见问候和应用身份问题直接回答，不调用模型或搜索。

## 环境要求

- Python 3.11–3.13；本机 Python 3.14 尚未完整验证。
- **仅在离线导入 Notion 文档时**，默认 Notion MCP 连接需要 Node.js 和 `npx`；首次导入会在浏览器中完成 Notion OAuth 授权。日常启动服务和问答都不连接 Notion MCP。
- DashScope API Key。仅在需要网络搜索回退时才需要 Tavily API Key。

## 快速开始

在项目根目录执行以下 PowerShell 命令。已有 `.env` 时不要再次复制示例文件，以免覆盖配置。

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

编辑 `.env`，至少填入 `AIROBOT_LLM_API_KEY`，并配置知识来源：

```env
AIROBOT_LLM_API_KEY=你的DashScope密钥
NOTION_PAGE_IDS=24fa020ef1cf80b68685fcfade70e314
```

如果只用 PDF，可将 `NOTION_PAGE_IDS` 留空。默认回答模型为 `qwen3.7-max`，路由模型为 `qwen-flash`，重排模型为 `qwen3.7-flash`，向量模型为 `text-embedding-v4`，音频模型为 `qwen3-asr-flash`。DashScope 的文本模型调用默认关闭思考模式以缩短等待时间；其他兼容服务不额外传此参数。问答页使用流式回答，长答案会逐步显示；模型请求 30 秒超时，页面会显示超时提示。默认地址是 DashScope 北京兼容接口；使用其他区域或兼容服务时，调整 `.env` 中的模型和地址。切换 embedding 模型后必须重新建索引。

先离线导入文档，再启动问答服务。导入命令会抓取 Notion、读取 PDF、按来源切分文档、调用云端向量模型生成 embedding，并把分块、向量索引和 BM25 统计结果保存到 `data/index/`。首次导入 Notion 时才会弹出浏览器授权，请选择能读取目标页面的工作区：

```powershell
python -m rag_agent.ingest
uvicorn rag_agent.app:app --host 127.0.0.1 --port 8000
```

打开 <http://127.0.0.1:8000/>。`GET /health` 中 `ready: true` 表示本地索引已加载；启动和普通问答无需再次授权 Notion。

### 通话模式

在桌面版 Chrome 或 Edge 打开问答页，点击“通话模式”，或直接打开 <http://127.0.0.1:8000/live>：

1. 点击“开始会话”，选择外部会议窗口或整个屏幕，并在浏览器共享对话框中勾选音频；随后允许麦克风。页面分别标记“面试官 · 电脑声音”和“我 · 麦克风”，状态栏显示实际麦克风设备。电脑声音来自共享来源的数字音轨，因此使用耳机通常仍能转写面试官。
2. 需要 AI 回答时，按下方“AI 回答开关”步骤操作。面试官停顿、实时识别给出完整转写后，才调用小模型判断；回答会逐步显示。
3. Windows 上建议在进入会议前点击“原生浮窗”，打开可置顶、拖动、滚动和调整大小的独立字幕窗口。网页继续负责共享音频、麦克风采集和转写；原生浮窗只显示网页当前可见的转写、答案和评价。浏览器原有的“悬浮小窗”仍可使用。结束后等待最后的转写完成，再点击“导出记录”下载 Markdown。确认导出后可以开始新会话，新会话会覆盖旧记录。

Windows 原生浮窗使用系统的非激活窗口属性，点击或拖动浮窗时通常不会让会议网页失去前台焦点。请先打开浮窗，再切回会议网页。它不能保证会议平台不会通过其他信号判断窗口状态，也不会绕过会议平台的共享或录制提示。通话网页必须保持打开，且启动会话时仍需在浏览器中授权共享音频和麦克风。再次点击网页的“原生浮窗”不会打开第二个窗口；关闭原生浮窗可点击右上角 ×，需要时再从网页重新打开。字幕通过本机服务内存同步，不写入 Notion。

原生浮窗处于“等待网页开始会话”时，可点击浮窗中的“打开通话页 → 点击「开始会话」”跳转到网页；如果通话页已经打开，直接切回原标签页即可。**浮窗本身只显示内容，不能代替网页发起屏幕音频和麦克风授权。** 在网页点击“开始会话”并完成授权后，浮窗会自动显示转写和可见的 AI 内容。

若所选共享来源没有音轨，页面会提示重新选择；浏览器对系统音频的支持取决于浏览器、操作系统和共享来源。

#### AI 回答开关

1. 开始会话后，点击控制按钮下方较小的 **“更多设置”**，展开设置区。展开后才能看到 **“AI 回答”** 开关；默认是关闭的灰色状态。录制双方转写不需要开启它。
2. 需要答案时，点击 **“AI 回答”**，开关变蓝。请在面试官**开始说问题之前**打开；只会判断开启之后开始说出的面试官发言，你的麦克风内容不会触发回答。它不会补答开启前已经说过的问题。
3. 再次点击开关即可关闭。若“回答与评价”也关闭，正在生成的回答会停止，页面和悬浮小窗会立即隐藏已有 AI 答案及判断状态；若“回答与评价”仍开启，它会继续回答并显示新听到的面试官问题。双方语音转写始终继续记录。重新打开开关，已生成的答案会重新显示；此后只回答新开始的问题。
4. 会话结束后也可以用这个开关切换**显示或隐藏**已有答案，此时不会再触发新回答。导出 Markdown 会保留本次会话已生成的答案和来源，即使页面上暂时隐藏了它们。

#### 回答与评价开关

开始会话后展开 **“更多设置”**，打开独立的 **“回答与评价”** 开关。这个开关默认关闭，不依赖“AI 回答”：打开后，系统会判断新听到的面试官发言是否为问题，只给出检索后的 AI 回答；你随后通过麦克风说出的回答会与最近的面试官问题配对，显示正确性、完整度、遗漏要点和补充回答。面试官和你的原始转写始终分别记录。请在面试官开始提问之前打开；开启前的旧问题和旧回答不会补处理。回答按停顿后的转写片段合并，约 2.5 秒后开始评估；若继续回答，会更新该题的评估。仅打开“AI 回答”时，仍只回答面试官问题，不评价你的回答。

再次点击开关即关闭，页面及悬浮小窗会隐藏此前的回答评价；若“AI 回答”也关闭，面试官问题的 AI 回答一并隐藏并停止生成。双方转写继续。重新打开时，本次会话已完成的内容会重新显示，后续只处理新开始的问题和回答。会话结束后，开关仅控制显示。导出的 Markdown 会保留已完成的回答和评价，即使当前隐藏。面试官问题固定先检索本地知识库；检索效果差时按配置尝试网络搜索，再生成回答。你的回答只复用该问题的结果做评价和补充，不另行检索；若没有可用依据，则标为“未经资料核实”。由于实时转写可能有误，评估仅作辅助参考。

技术主题短语（如“Webpack tree shaking”）也按隐含提问处理。AI 开启时，每条面试官转写会显示“判断中”“未识别为问题”“正在回答”等状态；未识别为问题时，可用“按这段话回答”手动触发。问题判断的小模型会在同一次调用中谨慎修正转写里明显的技术术语错误，原始转写仍保留在记录里；发音不清且无法从上下文确定的词不会猜测，可到问答页手动输入正确问题。回答沿用现有问答路由和知识库检索；若最终由模型经验回答，答案旁和导出记录中都会带“未经资料核实”标识。浏览器“悬浮小窗”需要支持 Document Picture-in-Picture；Windows“原生浮窗”需要本机 Python 安装包含 Tkinter。记录只保留在当前标签页的 `sessionStorage`；关闭标签页后清除，开始新会话会覆盖旧记录。应用不保存音频文件。

实时识别使用两路 `qwen3-asr-flash-realtime` WebSocket，会产生语音模型用量。可通过 `LIVE_ASR_WS_URL` 指向所在业务空间的实时 WebSocket 地址，`LIVE_ASR_MODEL` 设置模型名。密钥仍只保存在服务端 `.env`，不会发送给浏览器。建议使用耳机：会议音频仍从共享来源的数字音轨采集，耳机能避免播放声音再次进入麦克风。页面默认开启“防串音”，面试官说话时会暂停麦克风转写；如果需要记录双方同时说话，请关闭该开关。浏览器也会尝试启用更强的麦克风回声消除，但效果取决于设备和浏览器。

**启动服务只从磁盘加载已处理的分块、向量索引和 BM25 统计结果。** 启动时不会连接 Notion、解析 PDF、重新切分文档、重新生成 embedding 或重新为分块分词。问答时仍需调用云端模型生成问题向量、判断路由、可选重排和回答。新增或修改文档可使用下方的单来源增量命令；只有运行无参数的 `python -m rag_agent.ingest` 才会全量重建。导入后重启服务加载新索引；仅修改 `.env` 不会自动更新文档。

## 添加知识库文档

目前没有网页上传入口。文档由服务端离线导入，操作如下：

1. **上传 PDF**：把文件复制到项目根目录的 `data/pdfs/`。例如在 PowerShell 中运行 `Copy-Item "C:\路径\你的文档.pdf" .\data\pdfs\`。只扫描该目录下的 `.pdf` 文件，不扫描子目录；扫描版 PDF 需先做 OCR。
2. **添加 Notion**：在项目根目录的 `.env` 中，把页面链接末尾的 32 位页面 ID 添加到 `NOTION_PAGE_IDS`，多个 ID 用英文逗号分隔。需要导入整个栏目时填父页面 ID，并保持 `NOTION_INCLUDE_SUBPAGES=true`；页面需属于已经授权的工作区。
3. **处理并保存**：在项目根目录运行下方对应的增量命令。命令结束并显示 `chunks_total` 后，结果已写入 `data/index/`。导入失败时先检查错误，不能只重启服务。
4. **让问答生效**：首次导入后启动服务；运行中的服务则在导入完成后重启。打开 `/health` 检查 `ready: true` 和 `chunks` 数量。

新增或更新**一个 PDF**，只处理指定文件，不重新抓取 Notion、解析其他 PDF 或重新生成旧文档的向量：

```powershell
python -m rag_agent.ingest --pdf ".\data\pdfs\AI应用开发+后端面试题.pdf"
```

新增或更新**一个 Notion 页面树**，只抓取指定页面及其子页面；可传页面 ID 或完整链接。若它是新的根页面，也要把 ID 加到 `.env` 的 `NOTION_PAGE_IDS`，这样以后全量重建仍会包含它：

```powershell
python -m rag_agent.ingest --notion "https://app.notion.com/p/docker-3dea020ef1cf804f8caafa7a50f61d3e"
```

重复导入同一 PDF 会替换该 PDF 的旧分块；重复导入同一 Notion 页面会替换本次抓到的页面分块，不会重复追加。增量操作仍会根据现有分块刷新本地 BM25 文件，但只有指定来源会重新生成向量。删除源文件或删除 Notion 子页面后，需要运行无参数的 `python -m rag_agent.ingest` 全量重建，以清理已不在来源中的旧分块。网页问答和服务启动不会自动抓取新文档。

在问题中明确写“我的知识库”“这份文档”“根据我的 Notion 文档”等，会选择本地知识库。普通稳定概念不会自动查知识库；若希望按内部文档回答，请在问题中点明文档或提供**已导入**的 Notion 页面链接。未导入的 Notion 链接会提示先运行 `--notion` 增量导入，不会在提问时临时连接 Notion。

### Notion：多个链接

Notion 文档无需下载到本地。将每个链接中的页面 ID 写入 `.env` 的 `NOTION_PAGE_IDS`，用英文逗号分隔，不要直接粘贴完整 URL。例如链接 `https://app.notion.com/p/Webpack-24fa020ef1cf80b68685fcfade70e314?source=copy_link` 的页面 ID 是 `24fa020ef1cf80b68685fcfade70e314`。

```env
NOTION_PAGE_IDS=24fa020ef1cf80b68685fcfade70e314,aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
NOTION_INCLUDE_SUBPAGES=true
NOTION_MAX_PAGES=1000
```

建议只列出几个父页面：导入器会递归读取其子页面、按 ID 去重，并且不会跟随正文中的普通链接。分散在不同位置的页面可列出多个 ID。所有页面须对已授权的 Notion 工作区可读。若 MCP 返回内容中没有子页面结构，需要逐个列出页面 ID。超过 `NOTION_MAX_PAGES` 时导入会停止并报错。

默认使用 Notion 官方托管 MCP，通过 `npx.cmd` 启动 `mcp-remote` 桥接；非 Windows 系统将 `NOTION_MCP_COMMAND` 改为 `npx`。只读工具 `notion-fetch` 和参数 `id` 已在示例配置好。可运行 `python -m rag_agent.tools` 检查连接和工具参数。若使用自己的 MCP 服务，可配置 `NOTION_MCP_URL` 和相应的工具名；带 Bearer token 的 HTTP 连接可设置 `NOTION_MCP_TOKEN`。普通 Notion API token 不能直接当作托管 MCP token 使用。

### PDF

将可提取文字的 `.pdf` 文件放到 `data/pdfs/`，再运行导入命令。每页按来源保留文件名和页码。扫描件需要先做 OCR；当前版本不会识别 PDF 图片里的文字。网页没有 PDF 上传入口。

### 索引存储

导入后，LlamaIndex 的文档分块、来源信息和向量索引，以及预计算的 `bm25.json` 都保存在 `data/index/`。服务启动时只反序列化这些文件。旧版本已经生成 `data/index/`，但还没有 `bm25.json` 时，可以运行以下一次性离线迁移命令；它只读取已有索引，不重新连接 Notion、读取 PDF 或调用 embedding API：

```powershell
python -m rag_agent.ingest --prepare-existing-index
```

`data/index/`、`data/pdfs/` 和 `.env` 均被 Git 忽略，不随代码推送。换电脑或重新部署时，需要提供文档、配置和授权，再运行导入；或者复制可信的已构建索引目录，并保持 embedding 模型配置一致。

## 项目结构

```text
agent/
├─ rag_agent/
│  ├─ app.py             # FastAPI、问答页、健康检查和接口
│  ├─ config.py          # 读取 .env 和默认配置
│  ├─ engine.py          # 文档切块、建索引、检索、回答和音频转写
│  ├─ ingest.py          # 单来源增量导入、全量重建及已有索引迁移
│  ├─ bm25_store.py      # 离线 BM25 构建、保存和加载
│  ├─ live_audio.py      # 两路实时语音识别的 WebSocket 桥接
│  ├─ notion.py          # Notion MCP 读取及子页面遍历
│  ├─ retrieval.py       # 分词、RRF、语言和相关性判断
│  ├─ tools.py           # 查看当前 Notion MCP 读取工具
│  └─ static/            # 问答页和通话悬浮窗界面
├─ data/
│  ├─ pdfs/             # 待导入的 PDF
│  └─ index/            # 已处理分块、向量和 BM25 索引
├─ tests/                # 检索、Notion 和音频测试
├─ .env.example          # 配置示例；复制成 .env 后填写密钥
├─ requirements.txt      # Python 依赖
└─ README.md
```

## 主要配置

| 配置 | 用途 | 默认值 |
| --- | --- | --- |
| `AIROBOT_LLM_API_KEY` | 云端模型密钥 | 必填 |
| `AIROBOT_LLM_BASE_URL` | OpenAI 兼容接口地址 | DashScope 北京地址 |
| `AIROBOT_LLM_MODEL` / `AIROBOT_ROUTER_MODEL` / `AIROBOT_RERANK_MODEL` / `EMBED_MODEL` / `TRANSCRIBE_MODEL` | 回答、路由、重排、向量和音频模型 | 见 `.env.example` |
| `NOTION_PAGE_IDS` | Notion 入口页面 ID，多个用逗号分隔 | Webpack 示例页 |
| `NOTION_INCLUDE_SUBPAGES` / `NOTION_MAX_PAGES` | 是否遍历子页面及页面数上限 | `true` / `1000` |
| `BM25_ENABLED` / `RERANK_ENABLED` | 关键词召回和云端重排 | `true` / `true` |
| `WEB_FALLBACK_ENABLED` / `TAVILY_API_KEY` | 是否允许网络搜索及网页提取 | `true` / 空 |
| `VECTOR_TOP_K` / `BM25_TOP_K` / `FUSION_TOP_K` / `RERANK_TOP_K` | 各阶段候选数量 | `8` / `8` / `10` / `4` |
| `RELEVANCE_THRESHOLD` | 内部文档检索的可靠性阈值 | `0.70` |
| `MAX_AUDIO_MB` | 单个音频文件大小上限 | `7` |
| `LIVE_ASR_MODEL` / `LIVE_ASR_WS_URL` | 通话模式的实时识别模型和 WebSocket 地址 | 见 `.env.example` |

默认开启快速模型重排，以避免向量相似度低估正确文档。知识库检索结果低于 `RELEVANCE_THRESHOLD` 时，如已启用网络搜索并配置 `TAVILY_API_KEY`，会继续搜索网页；未配置搜索 Key、关闭网络搜索或搜索仍无结果时，由模型根据已有知识尽力回答。此类回答返回 `source_mode: model_fallback` 和“模型经验回答 · 未经资料核实”标签，不会伪造文档引用；最新信息、私有资料及高风险事实无法核实时会说明限制。未导入的 Notion 页面链接仍会提示先导入，模型不会猜测页面内容。`WEB_FALLBACK_ENABLED=false` 可关闭网络搜索。相关性阈值应结合实际问题校准，开启重排前后评分含义不同。路由对明确线索使用快速规则，对模糊问题调用一次模型判断是否需要查资料，因此可能增加少量延迟。索引构建、问题向量化、重排和回答会产生云端 API 用量。

## 常见问题

- **页面打开后提示没有索引**：先运行 `python -m rag_agent.ingest`，再启动服务。已有旧索引但缺少 BM25 文件时，运行 `python -m rag_agent.ingest --prepare-existing-index` 后重启。
- **新增页面后仍检索不到**：确认页面属于已授权的工作区、`NOTION_PAGE_IDS` 已更新；使用 `--notion` 导入该页面并重启服务。
- **Notion 授权失败**：检查 Node.js 与 `npx`、工作区访问权限，以及 `.env` 中的 MCP 配置。可先运行 `python -m rag_agent.tools` 验证连接。
- **扫描版 PDF 没有内容**：先用 OCR 生成可选中文字的 PDF。
- **没有检索到可靠资料**：检查文档是否已导入，或在需要网络回退时设置 `TAVILY_API_KEY`。
- **听得到面试官，但页面没有面试官字幕**：确认共享时勾选了音频。若提示没有音轨，重新选择整个屏幕或会议窗口；不同浏览器和会议软件对窗口音频的支持不同。
- **面试官的声音也出现在“我”的记录中**：优先戴耳机，电脑播放音频仍能从共享来源采集。默认“防串音”会在检测到电脑播放声音时短暂暂停麦克风转写；双方同时说话可能漏字，可关闭该开关。
- **戴耳机后“我”没有字幕**：先关闭“防串音”排查，确认状态栏显示的是实际麦克风而非“立体声混音”等虚拟设备，并检查浏览器的麦克风权限。关闭防串音后恢复，说明过滤过强，可继续在耳机模式下关闭它。
- **面试官说了话但没有 AI 回答**：确认“AI 回答”在这句话开始前已开启；等待完整转写和逐条判断状态。技术主题短语也可触发回答；若状态是“未识别为问题”，点击“按这段话回答”。若已识别为问题但回答失败，查看记录中的错误和模型配置。
- **更新代码后页面仍是旧行为**：先结束并导出正在进行的会话，再重启服务并刷新页面。刷新会中断正在进行的音频采集。

密钥只放在 `.env` 或部署环境变量中，不要提交到仓库。
